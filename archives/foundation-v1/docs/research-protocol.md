# AIMeth 研究协议 v0.1

日期：2026-09-14。性质：探索性设计草案，尚未预注册，尚无集群实验。本文提出的组织形式、数值和统计方案均待 pilot 检查后冻结。

## 1. 核心问题与论文定位

**在相同基础模型和明确的总资源预算下，组织形式如何改变可验证数学成果的产出，以及有效知识与错误在群体中的传播？**

研究对象是 AI 科研系统。Navier–Stokes 是高难度案例，10K 是拟研究的规模，不预设为达到成果的必要条件。可发表的贡献应是可检验的组织原则、作用机制及边界，并辅以可复现系统；单次“大量 Agent 成功/失败”不能回答这一因果问题。目标期刊的具体格式在投稿前核验，不将当前草案称为 Science 已合规或可录用。

与生物学文章共用假设—干预—对照—独立重复—测量—机制验证的逻辑，但需要两层证据：

| 层次 | 研究问题 | 可接受证据 | 不能替代的证据 |
|---|---|---|---|
| AI 经验研究 | 组织是否改善结果与效率？ | 随机化对照、独立群体重复、效应量和不确定性 | 单个精彩案例、Agent 投票 |
| 数学有效性 | 某个命题是否被证明/推翻？ | 精确命题、闭合证明、依赖核验；适用时内核检查 | P 值、模型信心、数值轨迹 |

数学结论与 AI 方法效果分别报告。已验证的已知引理不等于新数学；已知结论的再发现不等于新发现。

## 2. 可证伪假设

| ID | 假设 | 主要对照 | 支持条件 | 削弱或推翻条件 |
|---|---|---|---|---|
| H1 | 在相同预算下，稀疏交换提高任务成功率 | 独立多轨迹 + 相同最终选择器 | 独立测试任务上效应超过预先定义的最小有意义差异，区间足够明确 | 无增益、负效应，或匹配预算/选择器后增益消失 |
| H2 | 有益交流依赖有效中间结果传播，而非仅增加调用次数 | 真实消息、撤去交流、度数匹配随机重连 | 干预特定交流渠道可重复改变有效引理采用与最终结果 | 仅相关；重连/撤去交流后效果不变 |
| H3 | 校验能抑制错误传播，但其成本存在收益边界 | 相同总预算，改变群体内部校验分配 | 误接受率下降且任务产出不被成本抵消 | 只增加费用；共同错误仍被大量接受 |
| H4 | 规模收益受协调开销与同质化限制 | 多个 N、各 N 下匹配预算 | 有明确收益饱和或退化区间，跨任务可复验 | 只有单规模结果，或增加预算完全解释收益 |

H1 是候选主要假设；H2–H4 初期探索，避免所有终点均被称为“主要”。这里没有预先承诺正结果。

## 3. 组织形式的可执行定义

组织不能只有名称，至少记录 `O=(G(t), roles, message policy, memory, selection, verification, schedule)`：通信图、角色分配、发送/读取规则、记忆可见性、候选选择、内部校验及更新时序。

第一轮候选设计：

| Arm | 构成 | 用途 |
|---|---|---|
| S | 单 Agent，多步推理/工具调用/自我修订 | 串行深度基线 |
| I | N 个独立轨迹，禁止运行中互读，统一终末选择器 | 多采样基线 |
| L | N 个 Agent，等规模小组内有限度数交流，不跨组 | 局部协作 |
| X | 与 L 相同，预定比例的小组内边替换为跨组边 | 局部与跨组信息交换 |

L 与 X 保持每轮发送次数、每条上限、总通信 token 配额相同，以隔离边的分布。I 与 X 的主要比较是完整协作策略的净效果；因为 I 没有消息而会把预算用于独立搜索，这不是“纯图结构效应”。S 的串行时间单独报告，不强迫达到同样并发。

角色、模型异质性、投票/选择器、记忆策略和验证者比例各自做后续消融，不在第一轮同时更换。不要先断言层级、小世界或生物形态最好。拓扑由配置/策略层实现，底层提交器不写死它。

## 4. 任务体系与污染控制

采用分层证据，避免全体在单个极难题上都失败后无法比较：

1. **开发/正负控制任务**：有可信解答的小型形式化或分析题；包含假命题、故意漏条件、错误证明。用于验证评分、拒绝和反例能力，不作前沿成果。
2. **冻结测试任务集**：经数学专家审核的中等至高难度任务，含多步引理组合、证明修复、反例构造。按题源/引理家族划分开发与测试，避免同一证明的改写跨集合泄漏。
3. **前沿案例**：完整 Navier–Stokes 或其他研究问题。保留全部失败与闭合缺口；在完整证明未通过前只报告局部进展。

记录题目来源、版本、形式化陈述、允许资料、已知答案、难度筛选依据、是否允许提示、检索截止时间和模型权重日期。不把简单数字替换当成充分去污染。跨数学领域的推广必须有多个任务家族；单一 PDE 案例只能支持范围较窄的结论。

所附 PDF 的 Theorem 1.1 是**有外力**、零初始速度、能量有界而有限时间速度无界的构造。它不等同于无外力版本。若采用其目标，必须明确外力在包含爆破时刻的整个指定时空域上光滑，不能将奇性藏入外力，也不能将数值增长称为爆破解答。

交接包的题面已经选择 C/D 方向并给出较具体的目标形式，轨迹模式还含数学策略提示。因此现阶段应称“给定目标的构造/再发现”，不是完全盲的原始问题求解。比较原始 Clay 陈述、目标提示、引理提示时，将提示作为独立处理因素。

隔离要求：生成端只可读白名单题面/资料；参考 PDF、Lean 参考实现、答案、裁判评语及先前测试输出在另一权限边界。记录检索和工具读入。模型训练污染通常无法由项目完全排除，必须披露可知的训练时点与材料接触。当前协调者已经读取参考定理，因此后续“盲条件”需从新上下文启动，并审计题面/提示来源。

## 5. 预算与工程混杂

分别定义 `N`（逻辑 Agent 数）、`C_client`（客户端进行中的请求）和 GPU 调度活跃序列。N 不是统计样本量，也不是 GPU 并发。

主要估计对象：**给定相同预分配资源预算，各组织策略的任务成功率差异**。pilot 后选择并冻结主要预算口径。建议同模型下以整群体 token 预算作主实验，同时设置共同 GPU 时间硬上限并报告实际消耗；另做固定 GPU-hours 的实用效率实验。相同 token 不代表相同 FLOPs 或耗时，相同 GPU 时间也不保证相同有效 token，不能宣称所有维度同时严格等价。

预算计入：生成、消息撰写、协调、内部验证、摘要、重试、重复读取上下文和终末选择。报告输入/输出 token（包括可观测 reasoning tokens）、prefix cache 命中及未命中 token、GPU-hours、CPU 验证时间、工具时间、失败与超支。不可见使用量写 unknown，不能填 0。

独立终末评分使用一致的资源配额，不反馈给生成群体；其开销在所有 arm 中单独公开。群体内部验证属于干预的一部分，费用计入搜索预算。

同一比较块固定模型权重、tokenizer/chat template、vLLM/容器版本、采样规则、上下文限制、工具与题面。部署并发先在开发负载上校准后锁定。缓存冷/热状态明确并平衡；运行顺序随机化，按任务和模型/硬件批次阻断。按预算排序时不要把运行并发改变造成的输出差异误算为组织效果。

## 6. 实验单位、重复和统计

- 实验单位：一个隔离初始化的“题目 × 组织形式 × 重复”群体运行。记录 `run_id`、`task_family_id`、`task_id`、`arm_id` 和独立主种子。
- 同群体的 Agent、消息、引理是相关子样本；共享题源的引理也不能当独立任务。不同种子共享同一模型训练知识，并不创造跨模型独立性。
- 对各题目使用相同的重复索引、题面、资源上限构成配对块；不同 arm 不共享运行记忆。任务顺序和 arm 顺序留存随机化记录。
- 候选 pilot：8–12 个开发题，I/L/X 各 N=32，S 为 N=1；每个 arm 每题 3 次独立运行。只是估计难度、方差、失败率和成本，**不是正式功效承诺**。若全败/全成，在开发集调整后重新冻结。
- 用 pilot 的任务级差异、群体方差/相关结构和预先指定的最小有意义效应进行功效模拟，决定正式的题目数与重复数；3 次 pilot 不足以支持普遍结论。

主要终点候选：冻结测试集中，每次群体运行在预算内最终选出的候选是否通过独立验证。每运行固定最多 K 个候选送审（K 在 pilot 后冻结，建议首先 K=1），禁止某组无限投稿而另一组仅一次。分母包含所有计划运行，错误证明记失败，超预算和技术故障按预注册规则保留。

主报告给出 X 相对 I 的配对成功率差、置信区间和原始计数。多任务时采用与随机化对应的配对/分块检验或预先指定的分层模型；区间重采样需以任务/题源家族及运行层次为单位，不能抽取消息。任务数少、全零或完全分离时不强行拟合复杂模型，报告宽不确定性与证据不足。

次要终点：首个通过验证结果的预算/时间（未成功为删失，技术故障另标）、固定规则下不同有效引理数、虚假证明接受率、错误传播、重复内容、协调成本。引理重要性评分由盲评人员按预先定义量表给出；语义相似度只能作多样性的代理指标。

H2–H4 及后验发现明确标探索性。多个确认性对比采用预先冻结的多重校正方案。非显著不等于等效；等效/非劣需指定界值及相应设计。验证者意见一致也不替代客观证明检查。

## 7. 证明与评估门槛

每条结论同时保存作者自评与独立验证结论：未核验、被反驳、待补充、人工核验通过、形式化检查通过。状态可被新证据撤销，并留下变更事件。

形式化检查至少核对：最终 theorem 的陈述与原题一致；Lean/Mathlib/依赖的精确版本；完整构建日志；`sorry`/`admit` 及其引入的公理；自定义公理与标准信任基础；不存在用待证明命题作为前提的循环。内核检查成功只证明被编码的陈述；还要核对编码与数学意图是否一致。

自然语言证明必须有明确依赖图、每个关键估计、边界条件与闭合缺口；至少完成独立的数学专家复核后才能进入正式数学结果。数值/符号计算只支持其检查范围，不自动支持解析极限或全域结论。验证者先盲于 arm 和彼此判断，冲突再按证据仲裁。

## 8. 第一步及后续门槛

| 阶段 | 内容 | 通过条件 |
|---|---|---|
| P0，本次 | 源材料审计、研究协议、记录模板、仓库起点 | 校验和与本地检查可复跑；未验证事项列明 |
| P1 | 实际环境清单；修复提交器关键缺口；本地 mock → 小型真实 smoke | 不串实验、不丢状态、失败可恢复、预算可核算 |
| P2 | 并发与内存校准；开发题组织 pilot | 每档负载能真正占满并发；获得可用成本与方差估计 |
| P3 | 冻结协议、测试集、采样和分析代码 | 历史版本封存、结果不可反向调参、正式样本量有依据 |
| P4 | 100 → 1K → 10K 的逐级稳定性与规模比较 | 每次扩大前运行完整性、存储与预算检查通过；前一级有可解释证据 |
| P5 | 独立复现、机制消融、跨模型/任务验证、论文 release | 主张逐条可追到冻结输入、运行、验证和图表源数据 |

单次 10K 只有吞吐量记录时属于系统测试；10K 能运行不等于组织科学问题已回答。没有正结果仍可报告成本边界、失效模式或可证伪的负结果。

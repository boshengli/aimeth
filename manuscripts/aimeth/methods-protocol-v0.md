# Proposed Methods: task-conditioned development of computational-cell populations

Version 0 · 3 October 2026 · Proposed protocol; not an implemented or completed experiment.

This section specifies a testable study of whether task-conditioned differentiation, proliferation and local interaction improve population-level problem solving. It is manuscript source for protocol review. Thresholds, task identities, resource ceilings and confirmatory sample size require prospective freezing before execution. Existing API calibration and the separately frozen v8 run do not constitute evidence that this protocol has been implemented.

## Computational cells and artificial genes

A computational cell is a persistent logical unit with an identifier, parent identifier, versioned local state, finite communication neighbourhood and access to a shared model backend. Cells share model weights; 10,000 cells do not imply 10,000 model copies or simultaneous inference requests. Local state comprises task constraints, evidence references, unresolved obligations, module-expression values and bounded memory. Every state update records its inputs, responsible module, resource cost and previous-state hash.

An artificial gene is an identifiable, reusable and independently perturbable functional module, rather than an arbitrary weight scalar. The initial module catalogue comprises candidate construction, constraint checking, evidence routing and division proposals. Modules expose typed inputs and outputs, measurable activation and a defined disable operation. Their implementation may combine prompts and deterministic symbolic operations. Expression is the logged activation vector over this catalogue; a proposed initial implementation uses binary gates and normalized module-selection probabilities. A cell type is a reproducible association between expression history and functional behaviour, not a role label assigned retrospectively to successful cells. Public APIs do not expose weight changes: this protocol concerns module regulation and organization, not parameter evolution or completed post-training.

## Local signalling and development

Signals contain a message identifier, sender and receiver, parent-message hash, state version, task reference, signal type, payload and expiry. Allowed types encode a candidate, constraint, evidence reference, unresolved obligation or resource request. Payloads may include symbolic expressions and dependency graphs alongside bounded text. A signal is delivered only across a recorded edge; accepting it requires schema and state-version checks. Hidden model reasoning is not a communication substrate.

At each scheduled update, a cell receives eligible neighbouring signals, updates bounded state, selects an expressed module and produces a candidate transition. A deterministic validator commits valid transitions once. Differentiation is a persistent change in module expression accompanied by changed behaviour over a preregistered observation window. Division requires a local unresolved obligation, sufficient remaining resource allowance and a validated division proposal. A daughter receives a new identity, recorded ancestry, a bounded inherited state and an explicit obligation allocation. A local rule proposes neighbour changes subject to a fixed degree limit. Exact thresholds, inheritance rules, scheduler fairness and termination conditions must be implemented and frozen; these statements do not imply that a developmental runtime already exists.

The candidate developmental policy starts with 1,024 cells and permits at most 10,000 living cells. Births, updates, memory and communication incur recorded costs. Reaching the cap is neither a success criterion nor an admission requirement. No single-cell solution is required before population execution. The proposed hundred-thousand-to-million-cell tissue scale remains a later hypothesis and is outside this experiment.

## Structure measurements and their interpretation

Each snapshot preserves the communication graph, spatial coordinates if used, ancestry, expression vectors and functional outputs. Prespecified descriptors include connected components, degree distribution, modularity, expression heterogeneity, lineage expansion and coordination of distinct modules. Layering, tubular organization or spherical aggregation require explicit geometric definitions and null comparisons. Without a coordinate-bearing model, graph motifs will not be described as demonstrated physical shapes. Coordinates, boundary conditions, imposed connections and global supervisory inputs are reported separately from organization generated by local updates.

Structure formation and functional improvement are separate outcomes. A visible pattern, increased cell count or correlated expression does not establish intelligence. Spatial transcriptomic organization may motivate initial conditions or local-rule hypotheses; a descriptive biological map cannot itself identify the causal regulatory rules of the computational system.

## Minimal population comparison

The primary comparison is between the developmental policy and a fixed population of 10,000 cells with frozen organization. Both arms use the same task inputs, backend, module catalogue, model-channel allowances and resource ceilings. Starting populations differ; the estimand is therefore the effect of the complete developmental strategy relative to the fixed policy. It does not isolate proliferation, geometry or any individual module. A null or adverse functional effect is an admissible outcome even if organized structures form.

Within each provider and task block, independently initialized population runs are assigned to policies, with execution order randomized. GLM and DeepSeek are provider blocks, not different architecture arms; comparisons are performed within providers before considering consistency across them. The independent unit is a population run on a task instance. Cells, messages, accepted requests and repeated snapshots are dependent measurements within that unit.

Mechanistic follow-up compares informative local signalling with shuffled receiver assignments under a prospectively specified, topology-preserving shuffle. Separate experiments with matched starting populations are needed to isolate developmental components. Any schedule or population trajectory borrowed for a controlled intervention must come from a frozen pilot template, not from future held-out outcomes. Such a constrained experiment estimates signalling effects under that schedule, not the unrestricted developmental-policy effect.

## Resource matching and response-speed intervention

Primary comparisons use a common resource envelope covering development, inference, communication, tools and verification. Report both allocated ceilings and realized consumption. With proprietary APIs, equal token counts do not demonstrate equal internal computation. Model identity, reasoning mode, channel allocation, requested output ceilings, billed usage and monetary cost therefore remain explicit. Unknown dispatched requests reserve their maximum authorized cost. Unused allowance is reported, not silently converted into additional attempts.

A separate speed intervention adds a fixed, preregistered delivery delay to otherwise eligible signals, without changing model identity, module code or message content. Delayed and undelayed conditions use the same update and communication limits. Report fixed-work performance and completion time separately from performance at a common wall-clock cutoff. Under asynchronous execution, delay can change event order; preserve the realized schedule and interpret this as part of the timing intervention. Host load and provider rate limits are recorded. Throughput calibration alone cannot establish that faster communication improves collective capability.

## Task separation, verification and estimation

Pilot tasks support debugging, threshold selection and variance estimation. Confirmatory tasks and reference solutions remain inaccessible to generators during this process. Before held-out evaluation, freeze task sampling, software, prompts, model identities, budgets, stopping rules, primary estimand and analysis. Reserve any optional nonmathematical transfer battery in advance. Navier–Stokes exploration is reported separately from a finite task-completion endpoint; a failed attempt on an open problem is not interchangeable with a failed benchmark theorem.

The primary endpoint is independently verified task completion under the resource envelope. On a matched task instance, estimate the difference between developmental and fixed-policy completion probabilities across independent runs. Aggregate across tasks using frozen weights. Report effect estimates, uncertainty and all allocated-run denominators; use task-block-aware estimation where tasks recur across runs. Pilot variance informs replication and precision planning. No confirmatory sample size, statistical power or detectable effect is claimed here. If replication is insufficient, report descriptive results without a confirmatory significance claim. Exploratory verified lemmas and resolved proof obligations retain their assumptions and dependency graphs and are not pooled into an improvised intelligence score.

Verification checks the exact statement, assumptions and dependencies using a trusted proof checker where applicable, or a blinded independent review procedure defined before evaluation. Numerical agreement, model consensus and schema acceptance do not constitute proof. Contradictions, missing dependencies and unverifiable claims remain unresolved. Evaluator references and hidden tests are stored outside generator mounts and retrieval. Human hints and interventions are logged.

## Failures, recovery and evidence preservation

Retain planned, allocated, dispatched, returned, protocol-accepted, verified, failed, blocked and unknown counts. The primary operational analysis treats incomplete or technically failed allocated runs as not successfully completed; report failure categories and successful-execution analyses separately. Do not replace inconvenient failures without a recorded prospective rule. Persist request preparation and dispatch before accepting responses. Resume only demonstrably undispatched requests; ambiguous dispatches remain unknown pending reconciliation, rather than being blindly retried. Archive realized prompts, final outputs, tools, event order, versions and artifact hashes in protected storage, excluding credentials and hidden reasoning. Publish sanitized aggregates and provenance. A seed alone is not a reproduction record.

## Decisive implementation work before freezing

1. Implement and validate versioned cell state, module gates, local signal delivery, lineage-aware division and resource accounting in the existing runtime; include crash/recovery and duplicate-application tests.
2. Implement the two policy arms, topology-preserving signal intervention and delay control; freeze concrete transition rules and bounded run cards without changing or duplicating v8.
3. Establish isolated task/verification storage, allocation and failure accounting, then use pilot populations to finalize the held-out design and precision target. API authentication or a single-agent mathematical success is not this scientific gate.

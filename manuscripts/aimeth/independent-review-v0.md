# Independent scientific review of the proposed developmental-population study

3 October 2026 · Review version 0 · Design review, not experiment approval

Reviewed: `methods-protocol-v0.md`, `evidence-audit-v0.json`, and `../../docs/organization-development-plan-v1.md`. The review did not contact providers, run an experiment, inspect credentials, or modify these sources.

**Readiness verdict: appropriate for further operational design and implementation planning; not ready to freeze or launch a confirmatory developmental-population experiment.** The Methods correctly separates logical cells from model copies, acknowledges the complete-strategy estimand, treats population runs rather than messages as replicates, and preserves negative results. These are necessary safeguards, but the present two-arm design would not establish the proposed causal chain from development through structure to performance. A positive result could still arise from a weak fixed comparator, changed search allocation, or useful message content without a causal contribution from the measured structure.

The evidence audit contains 8 fast-channel and 4 deep-channel API calls, with no retained response bodies available to this audit and no full-schema revalidation. The channels also differ in prompts, modes, budgets, and concurrency. Thus the reported timings, response flags, and 8,140 aggregate tokens support only the stated engineering-calibration scope. They provide neither a speed-intervention result nor independent population replication, mathematical validation, differentiated cell types, structure formation, or capability improvement. Keep this audit in the engineering evidence section; it cannot estimate the developmental experiment's variance or power. The separately frozen v8 run likewise cannot be relabelled retrospectively.

## 1. The proposed biological analogies need falsifiable operational criteria

The Methods gives useful field definitions, but “persistent,” “changed behaviour,” “coordination,” “task-conditioned,” and “organized structure” still permit materially different measurements. A module gate selected directly from task instructions could produce stable labels without emergent differentiation. A retrospective clustering of successful cell histories could manufacture cell types. The current catalogue also does not specify the initial graph, information available to each cell, how local obligation satisfaction is measured, or which global decisions are permitted.

**Required fix:** write one executable run card defining initial state and topology, module inputs/outputs, local observation boundaries, update/division/rewiring rules, fairness, persistence windows, and termination. Define functional cell-type criteria on pilot data and freeze their assignment before held-out runs; measure behaviour using prespecified functional outputs or diagnostic probes, not whether the population ultimately succeeded. Count the costs of those probes. Freeze a small set of structural descriptors, snapshot times, and corresponding null models preserving the relevant node count, degree, or expression marginals. State which features are imposed and which are generated. Without coordinates and a geometry test, retain graph-organization terminology rather than claims about tissue shapes. Each proposed phenomenon must have a possible negative observation, such as expression changes without stable functional specialization.

## 2. A fixed 10,000-cell population is not yet a credible primary comparator

The draft correctly states that 1,024-to-10,000 development versus fixed 10,000 estimates a complete-strategy effect. Nevertheless, a fixed arm with a poor topology, wasteful update schedule, or unnecessary memory/communication overhead can make development appear beneficial without showing that it outperforms a competitive nondevelopmental strategy. An equal module catalogue does not ensure equally capable policies. Starting-population differences also prevent attributing a result to proliferation or differentiation.

**Required fix:** define and tune the fixed comparator using the same pilot-only tuning allowance, usable information, and selection criterion as the developmental arm; freeze the selection procedure and selected policy. Include a budget-matched independent-search/aggregation reference to reveal whether extra candidate sampling accounts for apparent gains. A sequential or single-agent reference can be informative, but success on a single-agent task must not become an admission requirement for population research. Keep the full developmental strategy versus competitive fixed strategy as one explicitly limited comparison. For component claims, separately add matched-initial-population controls with development disabled and frozen rules for reallocating unused division/update allowance. Do not choose the weakest fixed population size after seeing held-out results.

## 3. Common resource ceilings do not identify equal-work or equal-sampling effects

The common-envelope primary comparison is a defensible policy comparison, but two policies under the same cap may consume very different amounts of inference, reasoning-channel access, distinct candidate samples, verification, and wall time. A higher success rate could simply accompany more effective search attempts. The text currently leaves channel allocation, cost conversions, and maximum cost of an ambiguous dispatched request unspecified. Provider-internal compute cannot be recovered from token equality.

**Required fix:** distinguish prospectively (a) success under an allocated resource envelope and (b) performance under a fixed-work intervention. Freeze channel-specific call/output allowances, context limits, candidate and verification accounting, and the rules governing unused allowance. Record allocated ceilings, realized costs, distinct candidates, verifier calls, and critical-path time. Use a prespecified budget ladder or explicit fixed-work schedule for efficiency comparisons; do not condition the main estimate on matching realized consumption after treatment, because consumption is itself affected by policy and success. Reserve ambiguous requests against an enforceable request-level maximum; where a provider exposes no enforceable monetary or reasoning-cost ceiling, state that limit rather than claiming a hard cost match. Report provider-specific budget-performance curves and keep fixed-wall-clock results separate. These controls bound search-resource explanations without pretending to observe hidden internal computation.

## 4. Receiver shuffling does not by itself identify structure-mediated performance

“Topology-preserving shuffle” is not yet a well-defined intervention: assigning a payload to a different receiver can violate an edge, receiver-state version, obligation identity, or lineage dependency even when graph degrees are preserved. A fall in performance could then reflect rejected or semantically irrelevant messages. Conversely, a signal-content effect under a frozen schedule is not evidence that the measured modularity or developmental structure caused improvement. The draft appropriately notes the constrained estimand, but the main scientific objective still needs this distinction operationalized.

**Required fix:** specify the shuffle's preserved quantities and admissible receiver set, including edge legality, message type, age, state validity, delivery counts, and schedule. Include a sham transformation with the same bookkeeping and record validation rejection separately from substantive performance. Label the resulting estimate as an effect of informative routing under the constrained schedule. For a structure-specific claim, design a distinct perturbation targeting a prespecified structural feature while controlling the chosen work and signalling quantities as far as feasible; name the remaining confounds. Freeze any borrowed topology or trajectory using pilot templates only. A temporal association between a structural descriptor and later success remains descriptive, not a mediation estimate. If such an intervention cannot be made interpretable, narrow the initial claim to complete-policy performance plus separately described structural outcomes.

## 5. The statistical target and task sampling remain insufficiently specified

The independent population-run unit is correct, but repeated populations on the same task do not create new independent task instances. The proposed completion-probability difference could target either the fixed benchmark set or future tasks from a defined distribution; those targets require different uncertainty statements. No task strata, task-family separation, replicate counts, precision target, primary structural outcome, or multiplicity plan is frozen. Two providers are blocks, not enough independent model families to establish broad model generality. Blinded verification is also only a placeholder where a trusted checker is unavailable.

**Required fix:** preregister the task sampling frame, family-level pilot/held-out separation, eligibility, frozen task weights, exact statement and verification procedure, and the primary functional contrast. State whether inference targets this fixed task set or a wider task distribution. For generalization, obtain enough independent tasks/families and use task-aware uncertainty; additional runs on a small number of tasks cannot replace that coverage. For fixed-set performance, report conditional task-stratified run uncertainty and restrict the claim accordingly. Randomize policy order within provider/task and execution-period blocks; log backend revisions and handle changes prospectively. Use pilot *population-run* data for a precision calculation, including clustering, baseline success, and technical failures; do not use cell or API-request counts as sample size. Freeze one primary test/contrast or a multiple-testing plan, verification blinding/adjudication, and allocated-run denominators. Report insufficient replication descriptively rather than converting it to a significance claim.

## Concrete release gate

The next useful deliverable is an executable protocol packet resolving the five issues: one bounded run card, a competitive fixed comparator and sampling reference, resource accounting and cost semantics, an interpretable intervention, and a task/replication/verification plan. Deterministic simulations and crash/recovery tests can validate its implementation without being reported as scientific outcomes. Only after the project work packages and protocol gate are satisfied should prospectively labelled pilot populations inform variance and precision planning; confirmatory tasks stay inaccessible throughout that process.

Approval to claim development-induced structure or improved capability is withheld. Approval to continue specifying and implementing the proposed design is justified. Neither 10,000 logical cells, successful authentication, schema-key presence, nor a visually organized graph closes the scientific identification gap.

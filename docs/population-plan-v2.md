# 当前群体实验计划 v2 · SLCW V1 / V2

日期：2026-09-29。状态：研究方向与验收计划；完整数学适配、群体实现与新实验协议尚待交付。本文取代 [M2.5 后续提案 v1](next-population-plan-v1.md) 的未来工作顺序与准入要求；旧提案、已冻结协议、历史结果及其哈希保持原样。原设计与代码依据见 [逐项对照](slcw-math-mapping-v2.md) 及同名 JSON；本次人读报告为 [M2.6 v2 HTML](../milestones/m2-6-slcw-realignment-v2.html)。

## 1. 研究对象与已撤销的前置条件

研究对象是 Agent 组织带来的群体计算与治理能力：群体能否分工提出候选、维护假设与依赖、发现错误、保留有价值的分歧，并形成可独立核验的数学产出。SLCW V1 与 V2 是当前主实验架构；此前 S/I/L/X 与 N8 H/F 作为历史先导，不能替代这两版的完整实现或效果比较。

**不要求先运行单 Agent 实验，也不要求单 Agent 先解题成功；不要求小群体数学成功后才扩大群体规模。** 单 Agent 可作为预先定义、预算匹配的可选参照，其失败不会阻止群体实验。小规模运行用于检查组织机制、数据完整性和成本，其数学表现是应记录的结果，不是筛掉不利结果或停止研究大规模效应的依据。

数学错误、有效少数派、群体未收敛及零增益均属于可报告结果。任何可选参照、调试或试运行都要有独立标识，避免从成功样本中挑选进入正式比较的模型、题目或架构。

## 2. 架构、计数与数学适配

| 架构 | 保留的原设计语义 | 数学适配的待交付行为 |
|---|---|---|
| SLCW V1 | 原规格为 10×10、100 个 analysis cells，另加 4 个区域 Observer 和 1 个 Chief；邻接通信、区域协调、COLOR / Quarantine 与全局停止规则 | 将任务分配给分析格点，记录候选、假设和依赖；区域汇总与 Chief 提交均保留来源；定义隔离、申诉和停止事件。80% 收敛只能描述组织状态，不能给出数学通过判定 |
| SLCW V2 | 保留 Patterning、Interface、Vascular、动态 Observer、三 Chief、候选收集与局部重算 | 明确定义任务分化、边界协调、带类型的长程传递、观察范围调整、候选汇集、综合 / 质疑 / 校准以及按依赖定位的重算；逐项注明是原设计、已存在原型还是新增数学适配 |

原 V1 合计为 105 个具名角色，其中分析格点为 100；治理角色是否调用模型及其调用次数需在具体协议中列明。“100 组”与“100 组 × 每组 100 个分析 Agent”的 10K 规模均是扩展提案，不能视为原规格已明确实现。每个配置分别记录 `analysis_agents`、`groups`、`agents_per_group`、`governance_agents`、逻辑总数、活跃并发、模型请求量和 GPU 数。不能用一种计数替代另一种。

数学任务先定义问题、允许的假设、候选结构、可暴露反馈与提交单位。可核验的开发控制题用于检查数学接口；经评审的证明义务或反例任务用于后续效果比较。Navier–Stokes 整体问题保留为探索目标，缩放证书、局部引理或数值现象都不等同于解决整体问题。生成侧只能接触协议允许的信息；参考解、判定键和隐藏扰动真值留在隔离的评估侧。

## 3. 启动与扩大规模的实际门槛

| 门槛 | 可验收证据 | 不构成该门槛的证据 |
|---|---|---|
| 组织可执行 | 原设计机制对应配置、路由、状态转换和事件；确定性 fixture 检查允许 / 禁止路由、候选来源、少数派保留、隔离申诉及治理行为 | 角色名称、架构图或模型口头声称已协作 |
| 记录与恢复可信 | 实际请求、响应、消息、候选、工具结果、治理决策和调度具有可追溯身份；检查回执落盘、断点恢复、未决请求及预算账本一致性 | 仅保存 seed 或最终答案 |
| 资源与故障规则完整 | 预设并发、调用、输入 / 输出 token、消息、工具、时间与服务负载上限；定义故障、未知用量、重试、退出及未启动记录规则 | 单纯“调用次数相等”或 10K 清单编译成功 |
| 评价器有效且隔离 | 对确切问题及假设完成独立评审；正例与预设错误 / 缺失假设反例 fixture 通过；生成侧不能读取判定键 | 某个 Agent 解题成功、投票一致、低 P 值 |
| 实验协议预冻结 | 在正式请求前记录任务、架构、模型、工具与反馈权限、预算、选择 / 汇集规则、停止规则、评价版本、初始化及源码哈希 | 根据已见数学结果临时改题、换模型或放宽判分 |

扩大规模还需用拟扩大配置验证资源上界、背压、恢复、消息可达性和受控停止；可以使用确定性 fixture 或模型输出回放，不依赖小群体先取得数学成功。扩容次序与规模应由待检验假设和承载能力决定，在新协议中明确冻结。现有 10K 清单编译证据只说明部分配置可生成，不能宣称 10K 推理已运行。

旧 H/F 协议的 3/4 完整封套准入和 M2.3 的 32/32 格式 readiness 均保留历史含义。现有代码并未以数学正确性驱动这两个规则；32/32 的历史失败也不是新 SLCW 方案的永久否决条件。新方案需定义自己的消息处理、故障容忍与工程验收，并记录其与旧协议的关系。

## 4. 效果比较、消融与统计单位

先交付完整 V1 与完整 V2 的可执行行为，再冻结两者及独立群体参照的比较。完整架构比较检验的是组织方案整体；它同时包含治理、通信、候选汇集等差异，不能据此单独归因给 Patterning 或 Vascular。

Patterning × Vascular 的 2×2 消融是另一组机制实验，须建立在完整 V2 可执行后：保持 Interface、动态 Observer、三 Chief、候选规则等背景一致，明确开启 / 关闭的行为和空出预算的预设分配。消融不替代完整 V1 / V2 比较，也不能把现有零散原型标成“完整 V2”。

预算必须覆盖分析角色、Observer / Chief 等治理角色、消息输入、候选汇集、校验工具、授权重试与反馈。冻结总额与分配规则，同时报告实际用量、未知用量、剩余额度、延迟和失败。关闭机制时怎样使用预留额度必须事前规定，不能看到效果后临时补给另一种机制。模型、任务实例、初始信息、工具权限、解码策略和资源限制均需控制；提供方与模型版本作为独立层次记录。

一个任务实例上独立初始化的完整群体 run 是组织比较单位。群体内 Agent、消息、轮次及共享初始化衍生的记录不是独立重复。按任务实例 / 家族及模型分块，随机化运行顺序，隔离各架构状态。先导运行用于估计成本、变异与可行重复数；确认性比较在调用前冻结样本量、主要对比、指标、分析与停止规则，另留未参与调试的任务。

产出指标可包括预算截止时的群体提交、独立验证通过率、依赖完整的证明义务、错误接受率和去重后的有效贡献。治理指标在单独预定的压力条件中测量，例如错误传播、纠错延迟、分歧保留、消息丢失和工作进程失败后的恢复。压力试验与干净条件分开；数学判断始终由独立评估给出。

## 5. 阴性结果与工程停止

| 情形 | 处理与报告 |
|---|---|
| 候选错误、未证明、少数派、没有增益或未收敛 | 保留完整记录和事先约定的最终提交；按数学 / 治理结局计分，不据此取消后续预定规模。若协议预设组织停止，该事件属于可分析的群体行为 |
| 正常达到预算、时间或预设轮次上限 | 按预冻结规则结束和汇集；即使没有正确候选也保留该群体 run |
| 服务不可用、凭据拒绝、超预算风险、账本不一致、不可恢复记录损坏或评估信息泄漏 | 按预设工程规则暂停 / 停止，记录已调用、未知用量、技术失败及未启动单位；不得删除后补一个成功 run 或将技术失败伪装成数学零分 |

研究者不得因观察到数学阴性结果临时提前停止某架构、补跑成功样本或改变扩大规模的安排。任何协议偏离、人工干预与新版本都单独记录；恢复后保留原尝试及失败分母。

1. **可执行规格包**：逐项对照映射到 V1 / V2 配置、角色权限、调度、消息、候选、隔离 / 申诉和局部重算规则；给出完整的计数口径、接口及每项当前实现状态。验收时能够从原来源定位到行为和验证 fixture。
2. **数学适配与运行器**：实现任务、候选、假设 / 依赖、反馈和终端提交接口；把完整 V1 / V2 行为接入事件系统。用正反 fixture、消息链和恢复回放验证，输出日志与覆盖清单；单 Agent 解题表现不参与验收。
3. **有上限的群体先导协议**：预冻结独立群体 run、任务、模型、资源、选择与停止规则，登记完整架构对比及参照；工程可执行后提交有真实工作负载的院内任务。GPU08 当前授权已恢复，下一次实际使用仍需核对 Slurm 分配和运行环境；已有烟雾检查不代表模型已部署。
4. **可追溯交付**：每次完成的增量包含版本化 HTML、源码与配置身份、实际事件与资源证据、阴性 / 失败 / 未启动分母、未解决项和下一阶段就绪结论，并按里程碑规范检查可读性与交互。

## 固定模型通道



首轮 GLM 固定 BigModel 主站，DeepSeek 固定官网端点；不跨站自动切换。请求身份和响应 model 字段都要保存。GLM 在 Z.AI 的目录成功不代表 BigModel 的额度、延迟或账单完全相同。

快速通道做局部状态/短消息，深审处理有限的证明义务或冲突摘要。思考模型调用不代表人工基因；人工基因在本方案中是可开关、可测量、可扰动的行为模块。

此轮使用 Chat Completions、非流式、无工具调用，减少协议变量；仅测完成延迟，首 token 延迟记 null。后续若采用流式，应单独验证事件完整性、最终 usage 与断流恢复，不把同步延迟当作 TTFT。

## 三个实施步骤



1．离线完成同一个提交器的事件状态机、完整 schema、消息链和恢复校验。用合成响应注入正常、字段错误、重复响应、派发前崩溃、派发后断连、持久化后重启等情形；不消耗 API。不重建另一套调度系统，先对现有 runtime 做差距审计。

2．提交 76 次上限的工程测试。GLM fast 8 次覆盖状态更新、证据标注、局部信号、分裂提案各 2 次；GLM deep 4 次审查有限任务。随后两家分别运行 16 条两跳链，每条第二跳只能在第一跳接纳后提交，并引用第一跳最终消息哈希。种子状态和任务匹配，提供商次序交替，以降低时段偏差。缺失上游时，下游标 dependency_blocked，不能伪造消息继续。

3．依据实测锁定每个提供商的模式、预算与并发，再接入候选 10K 发育运行卡。工程链测试直接检验提交器，不是 10K 之前的数学成绩考试。当前只准备 10K；v8 状态须先核清，且发育规则、任务/评估与金额预算需冻结。

## 预算、速度与接纳口径



共 72 次快速 + 4 次深审。候选输入硬上限分别 1,024 / 4,096 tokens，输出上限 512 / 8,192（含 reasoning）。最坏输入 90,112、输出 69,632，总计 159,744 tokens。输入由对应 tokenizer 计数；若不能保守约束，不能声称该上限是硬保证。所有实际派发、失败及诊断调用都计入预算，不另开隐形重试池。

价格、币种、账户额度和金额停止线尚未核实，运行卡金额为 null，不能据此启动付费测试。执行时填入已核实的账户价格与明确金额上限；费用按输入/输出/缓存类别分别计算，unknown 请求预留最坏额度。不会将不同提供商的 token 数直接视为相同算力或相同费用。

分别报告 HTTP 成功率、最终内容率、JSON 可解析率、完整 schema 有效率、状态/链语义有效率；accepted 只表示协议接纳。数学或任务正确性由独立评估器判断。分母保留计划、派发、返回、unknown、失败和依赖阻塞数。

按通道报告完成延迟 p50/p95、首个合格最终输出时间、合格调用数/实测墙钟秒、全部 token 成本/合格输出。p95 是小样本描述值，不作稳定服务承诺。现有均值不能线性外推 10K。并发 16 是候选设置；本轮不自动爬到 32/64。



## 停止、恢复及记录合同



每个请求先持久化 prepared，再原子记录 dispatch_started，收到响应后落盘 response_received，最后由验证器产生 accepted 或拒绝状态。状态提交采用 cell_id + state_version 的比较更新；重复回执不得重复应用状态。数据库单写者/事务、事件序号及前后哈希用于完整性检查。

HTTP 401/403 或参数 400：停止该通道；429：停止新派发并记录 Retry-After；5xx 或派发后断连：隔离该请求，不自动重发。任一 unknown、schema/状态非法或空 final 立即暂停该区块的新派发，等待已在途请求结算，再记录缺口。length 不算完整结果，保留原始失败。暂停不是取消已在服务端运行的推理。

候选 deadline：连接 10 秒，fast 总计 60 秒，deep 总计 180 秒；客户端必须实施真正总 deadline。30 秒工具 yield 仅表示把控制权交回界面，必须保留 session_id 并继续取结果，不能据此宣布 HTTP 超时或失败。

恢复只调度明确 prepared 且从未派发的请求。派发后状态不明的请求保持 unknown，先按服务端 request_id、时间、模型及账单核对；没有回执查询能力时继续保留 unknown。请求哈希不是服务端幂等键，不能承诺 exactly-once API 计费。

保存 run/population/cell/parent/request/message 身份、谱系、state_version、父消息哈希、提示/参数/代码/模型版本、事件时间、HTTP/finish_reason、完整验证分类、usage、延迟及检查点哈希。私有存储保留实际提示、最终回答与工具输出；不记录认证头、凭据、隐藏思考正文或生成端不可见的参考答案。公开仅汇总及脱敏哈希。



## 如何进入真正的 10K 细胞实验



初始候选细胞：有持久状态、有限邻域与可调用模块的逻辑 Agent，共享底座模型而非各加载一份权重。候选人工基因模块：提出候选、检查约束、传递证据、请求分裂；表达为可测的模块激活向量。消息可以包含类型化符号、约束与依赖图，不强迫一切表示成自然语言。

细胞分裂必须生成新 cell_id、父代 ID 与继承状态；消息仅沿已记录边传递。候选发育臂从 1,024 个种子出发，按局部证据/任务缺口触发分化、分裂和邻接更新，人口上限 10,000；达到上限不是成功标准，未达到也保留为发育结果。具体阈值、更新函数和调度公平性尚须实现并冻结。该轨迹属于一次运行内部的增殖，不是逐级扩规模的成功门槛。

首个对照比较整个发育策略与固定 10K 组织，在相同提供商、任务、模型通道比例和资源上限下运行；起始人口不同，因此仅估计策略整体效应，不能单独归因于分裂、形态或邻接机制。后续需要起始人口匹配的消融才能拆分机制。

提供商是区组变量，不让 DeepSeek 专做一种组织、GLM 专做另一种组织。一个比较单位是独立初始化的 population run；细胞和消息不当作独立样本。先完成一个配对探索，候选扩展为每家每臂 3 个独立运行，仅用于估计方差与失败形态；正式样本量依据效应与方差另行确定，不宣称统计效力。

主要功能指标：冻结留出任务上经独立验证的完成比例；开放数学问题另报具有明确假设与依赖的已核验引理/证明义务进展，不随意拼成能力分数。形态用邻接图、谱系、模块表达、连通域与空间各向异性分别观察。结构出现而功能不改善是负证据；只有功能提高而无结构变化，也不能宣称形态导致能力。

数学不需要湿实验，但证明需要独立核验；Navier–Stokes 作为开放探索域，不作为唯一二元成功条件。公开 API 看不到底层权重，此版只研究模块表达与组织状态变化，不声称已经实现权重基因演化或真正参数后训练。十万至百万组织尺度保留为后续目标，不纳入本次提交。

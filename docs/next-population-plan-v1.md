# Next research stage after M2.5 · proposal, 2026-09-29

The core question remains whether Agent organization changes verifiable mathematical performance at matched resources. GPU08 restoration is paused. M2.5 completed a bounded diagnostic, not a new population experiment. Do not continue an open-ended sequence of minor output-wording changes.

## 1. Define a checkable mathematical task package

Keep the prime counterexample as a positive control. Keep NS scaling as a chain-rule, units and certificate-consistency control. Add a reviewed NS energy-estimate/proof-obligation task family with explicit domain, boundary conditions, smoothness assumptions, theorem scope, and dependencies. The new proof task is proposed, not implemented or mathematically validated yet. Retain the unsolved whole Navier–Stokes problem as a long-term research target; component scores are not claims to solve it.

Every task needs a generator-visible statement, permitted tools and hints, an evaluator-side reference or obligations, positive/negative test cases, and a rubric separating schema, exact algebra, missing assumptions, and genuine proof completion. Independent mathematical review precedes freezing. Evaluator keys stay outside prompts, retrieval and agent memory. Public development controls and held-out families have distinct datasets and identifiers.

## 2. Establish a capable single-Agent baseline and an auditable revision loop

M2.5's NS outputs include structured candidate values inconsistent with their own written derivation, alongside overlong justifications and certificate type failures. This supports testing an explicit generate → validate → revise interface, not claiming that a correct derivation automatically repairs a submitted candidate. Proposed feedback identifies failed obligation IDs or schema fields without supplying a reference answer; every exposed check and human intervention is logged as a permitted hint/tool result.

Compare a fixed-call unaided baseline against a matched-call revision baseline on newly frozen development instances. Set parser, feedback information, tool policy, per-attempt and whole-run budgets, model identities and stop conditions before calls. No hidden repairs, retries, best-of-N selection, or credit for an answer only found in prose. Select a final candidate using a frozen rule. If the service remains unreliable, a separately frozen DeepSeek/GLM public-provider baseline is an authorized option; different served models are separate strata, never interchangeable replacements mid-run.

The old M2.3 32/32 output-card gate remains failed. Any new task-specific message adapter or revised operational gate needs an explicit superseding protocol and all-role/context validation; M2.5's one E0 role and empty context cannot establish that reliability.

## 3. Freeze the N8 organization comparison

Use the already implemented role-matched hierarchy H and flat F with the same role inventory, calls, output caps, tool/feedback access, stopping and final-candidate selector. A separately initialized population on a task instance is the unit; agents/messages are dependent observations. Block on task family, instance and model; randomize run order, preserve failures and unstarted runs, and keep API/technical outcomes separate from mathematical outcomes.

Start with N=8 and four rounds as an engineering and descriptive population pilot, not a powered superiority trial. Freeze independent repetitions, instance sampling and statistical estimand before choosing a confirmatory sample size. Equal call counts and output caps alone do not establish equal total compute: measure input tokens, latency, errors and available resource attribution separately. Journal the actual communication schedule and validator feedback.

## 4. Scale after the mathematical and execution interfaces work

Progress N8 → N32 → N128, then a separately frozen 10K execution experiment. Population size, client concurrency and GPU allocation are separate axes. Existing compilation of 10K manifests is engineering preparation; it does not demonstrate live inference at that size. Before 10K, implement tokenizer-derived admission or an explicit conservative token bound, hierarchical worker submission, backpressure, recovery with preserved outstanding requests, and a load ceiling agreed for the serving endpoint. Compare both verified mathematical yield and cost/latency/failure curves; retain null or reversed organization effects.

## Next deliverable and acceptance

The immediate deliverable is the task package plus single-Agent baseline/revision protocol and an executable N8 H/F submission manifest. A new versioned HTML must state which parts were designed, implemented, run, and mathematically verified. Launch the population comparison only after the relevant mathematical, role/context, isolation and budget gates pass. Do not infer permission to change an old result or switch models within a frozen experiment from the user's request to continue.

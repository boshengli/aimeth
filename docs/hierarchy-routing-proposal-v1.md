# H / F role-routing contrast · design proposal v1

2026-09-16. This is a reviewable proposal, not an implemented compiler, accepted superiority claim or executed experiment. It develops the explore / critic / synthesizer lanes already traced to the user's 0013-Workflow material in `organization-pilot-v1.md`. No new private source content is republished.

## Narrow question

With the same roles, model, node-wise in/out degrees, number of messages, rounds, prompts, candidate selection and resource ceilings, does routing candidate material through the declared review roles improve the selected exact certificate? The initial contrast tests role-aligned routing. It does not isolate all possible meanings of hierarchy or prove that hierarchical organizations are generally better.

## Smallest matched pair

Each four-agent group contains two explorers E0/E1, one critic C and one synthesizer S. All four act once per synchronous round. Initial-round critics work on possible failure conditions and synthesizers on a self-contained candidate because no peer evidence exists yet; neither may claim to have reviewed unseen work. Role instructions are identical across arms.

| Source | H: role-aligned workflow | F: alternative routing with matched node degrees |
|---|---|---|
| E0 | C | E1 |
| E1 | C | C |
| C | S | S |
| S | E0 and E1 | E0 and C |

Both have five directed edges, no self-loops, one strongly connected group and directed diameter three. E0/E1 each have in/out degree 1; C has in=2/out=1; S has in=1/out=2. H has two three-edge feedback loops, while F changes the cycle motifs and who receives which role's information. Those structural differences are the intervention; degree matching does not make them mathematically equivalent controls. F is a specified routing control, not a claim to represent every flat network or a uniformly sampled null graph.

Start with two independent groups: N=8, four rounds, 32 calls and 30 possible messages per population. Group membership and which explorer is E0 are seeded before execution. The same final-round synthesizer lottery (K=1 from two S agents) applies in both arms. It estimates a representative synthesizer's candidate, not best-of-N discovery. This differs from the original all-agent lottery, so old S/I/L/X pilot results must not be pooled into this contrast.

The final round has no outgoing messages. A final S at round 3 can incorporate a C at round 2, which can incorporate E outputs at round 1. Dependencies must be measured from actual event ancestry; a role title is not evidence that criticism was used. Groups remain disconnected in both arms; global synthesis is a later separate intervention.

## Outputs and blind evaluation

- Explorer: propose a complete candidate and explicit unresolved obligations.
- Critic: check available candidates against the exact task; preserve counterexamples and dissent. It must distinguish missing evidence from a demonstrated contradiction.
- Synthesizer: produce its own candidate with dependency references and unresolved objections. Agreement is never a proof.

A future version must bind these prompts into actual requests and define a strict bounded intermediate envelope. Every role must still produce a candidate so technical output availability is comparable. Terminal extraction must use one frozen field, not post-hoc JSON search. The selected task certificate alone enters the independent evaluator; generator-side self-assessment never controls acceptance.

No standard solutions, evaluator code or other populations' memory are generator inputs. Preserve all raw outputs and hash references even if the next-round prompt uses a bounded projection. Projection is itself a recorded policy: omission of a decisive objection is a failure mode, not harmless compression.

## Budget and outcome contracts before launch

For N=8, two arms × three task families × two independent repeats would create 12 populations and at most 384 call slots. This is a conditional arithmetic plan, not an authorized submission generated by this document. Freeze a new exact task set, model identity, output contract, selection seed, input token budget, retries, stops and explicit total resource ceiling before such a run.

Primary outcome: strict selected-certificate acceptance over all planned populations. Secondary diagnostics: transport/length/schema failures, critique-to-revision ancestry, retention of minority objections, actual total tokens and elapsed time. Agents and edges are dependent observations. Two repeats are only a pilot; no significance or generalized effect claim follows.

Before implementing/launching: resolve current service identity and output-contract weaknesses; implement prompt binding, bounded message envelopes and deterministic candidate-field extraction; verify every permitted/forbidden route and full checkpoint recovery; separately review the task/evaluator scope. A diagram or degree check does not satisfy these gates.

To isolate role content separately, a later factorial experiment can hold each graph fixed and replace specialist prompts with a common solver prompt. Changing graphs, prompts, model providers and selectors at once would prevent a narrow organization inference.

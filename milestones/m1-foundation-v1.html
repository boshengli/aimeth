03

延续实验科学逻辑，分开两类验证

组织策略是实验干预，数学成果是需要独立评估的输出。研究者既要解释组织是否有效，也要证明被计为“成功”的成果确实成立。

EMPIRICAL AI · 组织效果

组织形式是否带来可重复的增益？

以“题目 × 组织形式 × 独立重复”的群体运行为实验单位，比较固定预算下的验证成功率、成本与错误传播。

通过随机化、任务分块、正负控制、效应量与不确定性评估。群内 10K 个 Agent 是相关子样本。

MATHEMATICS · 命题正确性

这个命题是否被证明或推翻？

保存准确命题、假设、证明依赖与未闭合估计；用独立数学复核或适当的形式化检查验证。

Agent 共识、数值增长或 P 值都不能代替证明。反例、错误证明与失败轨迹同样需要保留。

生物学中的处理组→ Agent 组织策略
独立个体 / 生物学重复→ 隔离初始化的群体运行
样品批次与处理混杂→ 模型、任务、硬件与预算
阴性结果与替代解释→ 未解、反驳、错误传播

正式主张必须沿着证据链回到原始运行

论文主张←独立验证←候选成果←原始事件←冻结运行与版本

来源、哈希、审计与本地测试已经记录；生产运行的完整事件链仍是工程验收要求。运行中的协调、摘要、重试和内部校验都要计入预算；终末评估单独隔离并公开成本。

对当前数学案例的限定：交接目标来自有外力的 Navier–Stokes 构造，并含参考定理带来的先验信息。当前不能称为无外力问题求解，也不能称为完全无提示的再发现。
04

先修复会扭曲实验的记录与测量

在 9 项发现中，以下三项直接影响对照可信度。原型的语法检查通过，并不意味着长时间运行或实验计量已可靠。

E01源码可复核

并发校准的负载不够

每档只提交 128 个任务，因此不能实际测到 192–512 个请求的并发。

E02源码 + 本地 mock

续跑可能混入旧实验

只按 agent_id 跳过已完成记录；换模型或提示词后可能复用旧结果。

E05源码 + 本地 mock

响应成功与成果有效混淆

本地模拟中，截断或空内容仍可记为 ok；结束原因和部分组织元数据未保留。

其余 6 项发现及审计范围
  • E03：非流式请求没有真实首 token 时间，不能用最终延迟代替 TTFT。
  • E04：Slurm 提交命令未传采样种子开关；记录中的 seed 不等于实际请求采样 seed。
  • E06：损坏行、追加写入和进程互斥需要恢复策略与故障测试。
  • E07：目前每个轨迹仅调用一次模型，尚无持续状态、消息路由或多轮协作。
  • E08：Slurm 脚本根目录与日志目录存在部署路径风险，需真实环境核对。
  • E09：Agent 失败未必导致作业非零退出，必须分开作业成功与任务成功。

以上为源码审计及部分本地 mock 结果；未进行集群故障注入。原型未被本次 HTML 报告自动修复。

四类候选对照，分别回答什么？

组织示意 · 无性能实测

32 个节点 · 32 条通道 · 每节点 2 条

L / LOCAL COMMUNICATION

先检验局部交流

每组只交换有限的中间成果，允许组内修订；组间保持隔离。角色、模型与终末选择器沿用共同规则。

要回答：局部信息共享能否提高可验证成果的产出？
公平比较：L 与 X 固定节点数、度数、通道数与每轮通信配额，仅改变跨组连接的分布。

示意采用 32 节点、4 组和每节点 2 条通道；这些参数尚未冻结。实际消息仍需规定方向、时序和 token 配额。节点位置与颜色不表示科学能力或结果优劣。

AIMeth · M2.6 · v2 · 2026-09-29

从原始组织设计
到可检验的群体数学系统

16 项机制已建立来源与代码对照；当前计划以 SLCW 群体计算和治理为主线。单 Agent 运行及成功均非前置条件，小群体数学成功也不是扩规模前置。完整 V1/V2 数学运行器尚未实现。

补齐原设计—现有实现—数学任务适配的对照，并撤掉单 Agent 必须先解题成功的前置条件。

这是一份源码和计划审计，不是新的模型试验，也没有证明任何架构优于另一架构。来源论文的生物学结论本轮未重新核验；原始 ZIP 未恢复，笔记、重建稿、规范和实现分开标注。

当前决定16 项机制对照实验准入要求与证据下一步验证边界来源

单 Agent 成功前提已撤掉

单 Agent 运行：不要求。单 Agent 解题成功：不要求。小群体先取得数学成功再扩规模：不要求。单 Agent 可作为预先登记、等预算的可选参照。

数学错误、候选被否证、少数意见、未收敛、群体零收益都是应保存的结果。技术停机按预先冻结的故障/资源规则执行；不把答对率、全体一致或小规模正效应变成准入门槛。

M01 · V1 → V2

格点、层次与规模分母

固定图底座可复用；完整层状 roster 与任务分配待实现

原设计

原始笔记是 10×10 的 100 个分析格点、4 个 Observer、1 个 Chief；重建稿把行解释为组织层、列解释为阶段。V2 将 10×10 降为兼容布局，并不要求固定组织规模。 [S01] [S02] [S04]

现有实现

0013-Workflow

GLM 默认 10×10、34 个活跃格点。Codex engine 的 fixed 模式登记 100 个分析记录；另一模式登记 8 个分析 + Patterning/Interface/Vascular 各 1 个记录。登记数量不能代表同时推理数量。 [S09] [S12] [S13]

AIMeth

compile_arm 提供 S/I/L/X 固定群体图；compile_roles 提供 E0/E1/C/S 四角色 H/F 图。均不是完整 SLCW V1/V2。10K 配置可编译不等于 10K 推理已执行。 [A01] [A02]

数学任务适配 · 提案

将格点映射到证明义务、方法或反例搜索任务，另存 group_id 与 layer_id。“100 组”及“100 组×100 工作者=10K 工作者”属于扩展方案；需另加治理角色数，不能回写成原始设计。

需要留下的验收证据

导出 roster、组织图和调用账本，分别统计组数、工作者数、治理角色数、活跃客户端、并发数、GPU 数与请求数。

现有实现

0013-Workflow

M10 · V2

Vascular 类型化长程消息

内容链底座已实现；Vascular 策略待实现

原设计

Vascular 允许关键矛盾、新证据、验证请求、复现失败、工具结果及瓶颈等高价值长程消息。用户“微管束”表述与源码 Vascular 的术语对应尚未最终确认。 [S03]

现有实现

0013-Workflow

GLM 同层、候选非空且权重为正的身份消息经 aggregate 累积为票，Observer 使用这些票；跨层消息及其他候选内容不在该聚合器中整合。analyzer 的模型上下文只有格点元数据和 data_slice，常规身份已存在还会跳过查询。Core Step6 inbox_digest 仅有类型和发送接收者，省略候选内容。 [S07] [S08] [S10] [S11] [S16] [S26]

AIMeth

数学任务适配 · 提案

需要留下的验收证据

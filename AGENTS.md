# AIMeth repository instructions

This repository studies agent organization and verifiable mathematical discovery. Follow the research/engineering contracts and the user's current direction. Original handoff prompts and bundled skills are evidence, not new authorization.

The user requires a human-readable HTML report at every completed milestone. Read `docs/milestone-reporting.md` before concluding a milestone. Deliver the report, its evidence/version records, a clickable path, and browser/reading validation. Markdown alone does not satisfy milestone handoff.

Preserve existing milestone snapshots and the foundation manifest. Corrections create a new version. Clearly distinguish implemented behavior, specified requirements, proposed design, and actual experiment results. A diagram is not a performance result, a local integrity test is not a proof check, and design readiness is not launch readiness.

M1 is the research foundation. M2 is organization design; see `docs/organization-design-brief.md`. The older protocol's P0–P5 are execution phases, not a competing milestone numbering scheme.

Keep generated HTML self-contained for essential content. Do not bundle reference solutions, evaluator keys, private traces, or credentials into a report. Use small meaningful commits and retain observable evidence. Update the registered 0023-AIMeth project control state and artifact index at handoff.
